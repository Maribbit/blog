核心概念

什么是「账本」

账本是双循环共享的枢纽：分析循环不断写入并提升单元的「可兑现程度」，实现循环把达到阈值的单元取出交付、并回写「已兑现」。

“账本”，是把从原始需求拆解出来的可兑现单元集合。
可兑现单元

从原始需求拆解出的最小可交付切片，是账本的基本条目。

可兑现程度

随分析循环多轮迭代而上升：初始化 → 逐渐上升 → 达到临界（阈值）。

已兑现

切片通过用户测试后回写账本，标记该单元交付完成、已经兑现。

流程明细

八步流程

① ~ ⑤ 属于需求分析循环，⑥ ~ ⑧ 属于需求实现循环；两个循环通过账本衔接、交替推进。

循环一需求分析循环

1
列出原始需求

列出原始需求，要求 agent 实现需求。

阶段：原始需求
2
读代码 · 建立账本

agent 阅读代码和需求，对需求做拆解与可行性分析，建立账本（可兑现程度初始化）。

阶段：原始需求 → 读代码
3
反问用户

agent 发现阻塞性问题，向用户提问征求意见。

阶段：读代码 → 反问用户
4
回应 · 更新账本

用户回应后回到步骤 2，agent 判断合理性、更新账本（可兑现程度逐渐上升）。

阶段：反问用户 → 阅读代码 / 更新账本
5
达到临界 · 确认实现

重复 2~4，直到一部分可兑现单元达到阈值，向用户征求意见开始实现（可兑现程度达到临界）。

阶段：反问用户 → 回到账本

循环二需求实现循环

6
写代码 · 自测 · 交付

agent 实现切片并完成自测，向用户交付。

阶段：账本 → 写代码 → 反问用户
7
用户测试

用户测试：通过则进入步骤 8；未通过则回到步骤 6 继续实现。

阶段：反问用户 → 写代码 / 回到账本
8
更新账本 · 标记兑现

用户测试通过后，agent 根据切片范围更新账本：可兑现单元交付完成、已经兑现。

阶段：反问用户 → 更新账本
重复「需求分析 → 需求实现」双循环，
直到整个 Story 的所有单元全部兑现 ✓
